# P4 接口接入指南（参照 /cost 实现标准）

> 适用范围：在 **P4（agent.py，AI 智能交互后端）** 中接入一个新的 P3 数据分析接口
> （如后续的死亡风险分布 / 严重程度分布 / CMI 趋势 / 质量看板 / 异常预警 等）。
> 本文以 2026-08-21 接入 `/cost/*` 5 个端点的真实实现为蓝本，给出**逐点对照清单**。
>
> 维护：纪志鹏（P4 负责人）。改动仅涉及 `agent.py`，不触碰 P3 主模块与前端。

---

## 0. 前置条件（P3 侧已完成）

P4 只做"路由 + 消费"，不负责接口实现。接入前必须满足：

- P3 已提供端点：`GET http://127.0.0.1:5000/api/v1/<模块>/<接口>`
- P3 返回**统一信封**：`{"code": 0, "data": [...], "meta": {...}}`
- `data` 每项至少含 `key` / `value`（或 `pct`）/ `count` 字段（cost 端点就是这形状，可直接复用通用摘要/图表构建器；异构数据另写构建器，见 §7）

---

## 1. 总览：一个接口要改 8 处 + 自动继承 3 处

| 类型 | # | 注册点 | 位置（agent.py） | 作用 |
|------|---|--------|------------------|------|
| 手动 | 1 | Pydantic 输入模型 `_XxxInput` | Section B（~L2650） | 工具参数 schema（默认值/枚举） |
| 手动 | 2 | 参数构建 `_build_xxx_params` | Section C 前（~L2045） | intent → P3 query 参数 |
| 手动 | 3 | 路由表 `ROUTE_TABLE` | ~L2095 | chart_hint → endpoint/build/timeout |
| 手动 | 4 | 执行函数 `_execute_xxx` | Section C（~L2810） | 参数 → `_dispatch_chart_hint` |
| 手动 | 5 | 工具注册 `_TOOLS` | ~L2960 | 暴露给 LangChain Agent |
| 手动 | 6 | 摘要构建 `SUMMARY_BUILDERS` | ~L4006 | 文字回复（可复用通用） |
| 手动 | 7 | 图表构建 `CHART_BUILDERS` | ~L4876 | 前端 ECharts option（可复用通用） |
| 手动 | 8 | 关键词/标题/推荐问法 | 见 §8 | 规则兜底路由 + 展示元数据 |
| 自动 | — | `_VALID_TOOL_NAMES` | L3214 | = `ROUTE_TABLE.keys()`，**加路由即生效** |
| 自动 | — | `_normalize_tool_name` | L3222 | 自动去 `cost_/payment_/disease_` 前缀，防命名漂移 |
| 自动 | — | `_dispatch_chart_hint` | L2479 | 通用调度：取 endpoint/build/timeout，新路由自动可用 |

> ⚠️ **第 7 处（CHART_BUILDERS）最易漏**：漏注册会在 `generate_chart_config` 走
> `intent["metric"]` 分支直接 **KeyError**（接入 cost 时真实踩过）。8 处缺一不可。

## 2. 约定：chart_hint 命名

- `chart_hint` 是 P4 内部唯一标识，**同时也是 ROUTE_TABLE 的键**，全局唯一。
- 命名建议：`<模块前缀>_<语义>`。**避开 legacy 路由占用**：
  - `trend` 已被 `/analysis/trend` 占用 → cost 的趋势用 **`cost_trend`**
  - `aggregate` / `payment_mix` 同理被 legacy 占用，勿重名
- 工具名（`_TOOLS` 里的 `name=`）**建议与 chart_hint 一致**。
  cost 曾注册成 `cost_profit_difference`（带前缀）导致与键 `profit_difference` 不匹配、
  模型明明选中却被判"无效工具调用"降级 —— 现在两者已统一，新接口直接照此做，
  不要引入前缀差异（`_normalize_tool_name` 只是兜底，不是免死金牌）。

## 3. 逐点实现标准（以 cost 为蓝本）

假设新接口：`/api/v1/<mod>/<endpoint>`，chart_hint = `my_metric`。

### 3.1 Pydantic 输入模型（第 1 处）

位置：Section B，`_CostProfitDifferenceInput` 之后、`_OopBurdenInput` 之前。

```python
# 维度枚举：cost 用 Literal 限定合法值，非法入参 Pydantic 直接报错
_COST_DIMS = Literal["age_group", "diagnosis", "drg", "facility", "mdc", "payment_typology"]

class _CostProfitDifferenceInput(BaseModel):
    dimension: _COST_DIMS = Field(default="drg", description="分组维度")
    top: int = Field(default=20, ge=1, le=100, description="返回前N条")
    year: int = Field(default=0, description="年份，0=不限")
    filters: dict = Field(default_factory=dict, description=_FILTERS_DESC)
```

要点：
- 带默认值 → 模型参数缺省时也能调用（Agent 只填部分参数不报错）
- `ge/le` 限幅 → 防恶意大 top
- `filters` 统一 `_FILTERS_DESC`，透传 P3 12 种过滤白名单

### 3.2 参数构建函数（第 2 处）

位置：`_build_cost_profit_difference_params` 附近。

```python
def _build_cost_profit_difference_params(intent: dict) -> dict:
    params = {"dimension": intent.get("dimension") or "drg",
              "top": intent.get("top") or 20}
    if intent.get("year"):
        params["year"] = intent["year"]
    return params
```

要点：
- **只放 P3 端点认识的参数**，多余参数会被 P3 忽略或报错
- 维度翻译用**模块专属别名表**，不要动全局 `DIM_TO_P3_DIM`（那是 disease 模块的，
  会把 `payment_typology→payment` 反而搞坏其它模块）：

```python
# cost 专属：ccsr_diagnosis → diagnosis（P3 cost 端点只认 diagnosis）
_COST_DIM_ALIASES = {"ccsr_diagnosis": "diagnosis"}
# 使用：params["dimension"] = _COST_DIM_ALIASES.get(dim, dim)
```

### 3.3 路由表 ROUTE_TABLE（第 3 处）

位置：`_build_cost_trend_params` 之后、`ROUTE_TABLE = {` 内。

```python
ROUTE_TABLE = {
    # —— 模块三：费用成本分析（5 个，对接 /cost/*）——
    "profit_difference":   {"endpoint": "/cost/profit-difference",
                            "build": _build_cost_profit_difference_params,
                            "timeout": 60},
    # ... 新接口加一行：
    "my_metric":           {"endpoint": "/<mod>/<endpoint>",
                            "build": _build_my_metric_params,
                            "timeout": 15},
}
```

要点：
- `timeout` 按数据量选：百万级聚合用 **60**（cost 踩过 15s 超时），轻量查询用 15
- **endpoint 前必须有 `/api/v1` 之外的正确前缀**：P4 拼接 `ANALYSIS_API`（`http://127.0.0.1:5000/api/v1`）+ endpoint

### 3.4 执行函数（第 4 处）

位置：Section C，`_execute_cost_trend` 之后。

```python
def _execute_cost_profit_difference(dimension: str = "drg", top: int = 20,
                                    year: int = 0, filters: dict = None) -> dict:
    """查询费用成本差(各维度下总费用减去总成本的差额排名)。
    适用于"费用成本差""成本差""收支差额""费用减成本"等问法。"""
    return _dispatch_chart_hint("profit_difference", dimension=dimension,
                                top=top, year=year, filters=filters)
```

要点：
- **函数签名与 Pydantic 模型字段一致**（StructuredTool 按 schema 校验后调用）
- 内部一行调 `_dispatch_chart_hint(chart_hint, **kwargs)` —— 自动走 ROUTE_TABLE

### 3.5 工具注册 _TOOLS（第 5 处）

位置：Section C 末尾 `_TOOLS = [ ... ]` 内，`_CostTrendInput` 注册行附近。

```python
StructuredTool.from_function(
    _execute_cost_profit_difference, name="profit_difference",
    description=(
        "查询费用成本差(各维度下总费用减去总成本的差额排名)。"
        "适用于'费用成本差''成本差''收支差额''费用减成本'等问法。"),
    args_schema=_CostProfitDifferenceInput),
```

要点：
- `name=` 必须与 chart_hint 一致（见 §2）
- `description` 写清楚**适用问法**，这是模型选工具的依据，宁可多写同义词

### 3.6 摘要构建 SUMMARY_BUILDERS（第 6 处）

位置：`SUMMARY_BUILDERS = {` 内，cost 区段。

```python
SUMMARY_BUILDERS = {
    # —— 费用成本分析（对接 /cost/*）——
    "profit_difference":   _summary_cost,
    "profit_margin":       _summary_cost,
    # ...
}
```

- 数据形状是 `{key, value/pct, count}` 的**排行/构成/趋势类** → 直接复用 `_summary_cost`
- 异构数据（如桑基、热力、金字塔）→ 新写一个 `_summary_xxx`，参考 `_summary_sankey` 等

### 3.7 图表构建 CHART_BUILDERS（第 7 处，易漏！）

位置：`CHART_BUILDERS = {` 内，cost 区段。

```python
CHART_BUILDERS = {
    # —— 费用成本分析（对接 /cost/*）——
    "profit_difference":   _build_cost_option,
    "profit_margin":       _build_cost_option,
    # ...
}
```

- 排行/构成/趋势（`{key, value/pct, count}`）→ 复用 `_build_cost_option`（bar 图）
- 异构 → 新写 `_build_xxx_option`，参考 `_build_sankey_option` / `_build_pyramid_option`
- **漏注册 = 运行时 KeyError**（§1 警告）

### 3.8 关键词 / 标题 / 推荐问法（第 8 处）

三处配套，保证**无 LLM key 的规则模式**也能路由 + 展示元数据齐全：

```python
# (a) CHART_HINT_KEYWORDS（~L569）：规则引擎关键词 → chart_hint
"费用成本差": "profit_difference", "成本差": "profit_difference", ...

# (b) CHART_HINT_TITLE_ZH（~L5126）：中文标题（摘要/图表共用）
"profit_difference": "费用成本差",

# (c) SUGGESTED_QUESTIONS（~L3029）：前端推荐问法
{"tool": "profit_difference", "category": "费用成本",
 "question": "不同支付方式的费用成本差是多少？"},
```

## 4. 自动继承（无需改）

| 机制 | 说明 |
|------|------|
| `_VALID_TOOL_NAMES` | 每次提取时 `_init_valid_tool_names()` 从 `ROUTE_TABLE.keys()` 重建，**加路由即生效**，无需手动同步 |
| `_normalize_tool_name` | 提取时自动去 `cost_/payment_/disease_/analysis_` 前缀再校验，防命名漂移 |
| `_dispatch_chart_hint` | 从 ROUTE_TABLE 取 endpoint/build/timeout 并调 P3，含超时/连接重试 + 统一错误信封 |
| `_extract_tool_call_from_text` | 模型把工具调用写进文本而非标准 `tool_calls` 时，正则兜底提取并真实执行 |

## 6. 完整接入示例（一个最小新接口）

以"死亡风险分布"（假设 P3 已提供 `/api/v1/quality/death-risk`）为例，8 处改动的骨架：

```python
# 1) 输入模型
class _DeathRiskInput(BaseModel):
    dimension: Literal["age_group", "diagnosis", "mdc"] = Field(default="age_group")
    top: int = Field(default=20, ge=1, le=100)
    filters: dict = Field(default_factory=dict, description=_FILTERS_DESC)

# 2) 参数构建
def _build_death_risk_params(intent: dict) -> dict:
    return {"dimension": intent.get("dimension") or "age_group",
            "top": intent.get("top") or 20}

# 3) 路由表
ROUTE_TABLE["death_risk"] = {"endpoint": "/quality/death-risk",
                             "build": _build_death_risk_params, "timeout": 15}

# 4) 执行函数
def _execute_death_risk(dimension: str = "age_group", top: int = 20,
                        filters: dict = None) -> dict:
    return _dispatch_chart_hint("death_risk", dimension=dimension, top=top, filters=filters)

# 5) 工具注册（name 与 chart_hint 一致）
StructuredTool.from_function(_execute_death_risk, name="death_risk",
    description="查询死亡风险分布(...)。适用于'死亡风险''病死率分布'等问法。",
    args_schema=_DeathRiskInput)

# 6) 摘要（同构 → 复用通用）
SUMMARY_BUILDERS["death_risk"] = _summary_cost

# 7) 图表（同构 → 复用通用；漏了会 KeyError！）
CHART_BUILDERS["death_risk"] = _build_cost_option

# 8a) 关键词
CHART_HINT_KEYWORDS["死亡风险"] = "death_risk"
# 8b) 标题
CHART_HINT_TITLE_ZH["death_risk"] = "死亡风险分布"
# 8c) 推荐问法
SUGGESTED_QUESTIONS.append({"tool": "death_risk", "category": "质量安全",
                            "question": "各年龄段的死亡风险分布如何？"})
```

> 注意：`CHART_HINT_KEYWORDS` 和 `SUGGESTED_QUESTIONS` 是字面量 dict/list，
> 若直接 `ROUTE_TABLE["death_risk"]=...` 可，但 **dict 字面量内部的键要同步加**
> （推荐直接在源文件对应区块里加行，避免只改内存副本的错觉）。

## 7. 异构数据怎么办（不适用通用构建器时）

- 摘要：参考同类型已有构建器（桑基 → `_summary_sankey`，金字塔 → `_summary_pyramid`）
- 图表：参考 `_build_sankey_option` / `_build_pyramid_option` / `_build_heatmap_option`，
  返回 `{"chart_type": "...", "option": {...}}` 结构不变
- 只要 `data` 数组里每项有稳定字段名，构建器照字段取即可

## 8. 关键坑位速查（血泪史）

| 坑 | 后果 | 规避 |
|----|------|------|
| 工具名带模块前缀 ≠ chart_hint | 模型选中却被判"无效工具调用"降级 | `name=` 与 chart_hint 严格一致 |
| CHART_BUILDERS 漏注册 | `generate_chart_config` KeyError | 用 `test_chart_builders.py` 全量校验 |
| 动了全局 `DIM_TO_P3_DIM` | 其它模块维度翻译被搞坏 | 用模块专属别名表 |
| 趋势类 chart_hint 叫 `trend` | 与 legacy `/analysis/trend` 冲突 | 用 `cost_trend` 式带前缀命名 |
| dimension 透传 discharge_year | P3 报 400 | trend 类接口内部过滤冗余维度 |
| timeout=15 打百万级聚合 | P3 超时 | 按数据量选 15/60 |
