# P4 前端接口契约（agent.py · 5001 端口）

> 适用：P5 前端对接 P4（AI 智能交互后端）。P4 负责"问题理解 + 调 P3 分析 + 生成文本/图表"，
> 前端只需渲染 `answer`（文本）和 `chart`（ECharts option）。
>
> 维护：纪志鹏（P4 负责人）。更新代码后请同步本契约。
> 版本：2026-08-21（含 SSE 流式端点）。

## 0. 快速开始（最小对接）

```js
// 一次对话（同步版）
const resp = await fetch("http://127.0.0.1:5001/api/chat", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ question: "不同支付方式的费用成本差是多少？" }),
});
const data = await resp.json();
if (data.code === 0) {
  console.log(data.answer);            // 文本摘要（直接渲染）
  const chart = echarts.init(el);
  chart.setOption(data.chart.option);  // ECharts 配置（直接喂）
}
```

## 1. 端点总览

| 端点 | 方法 | 用途 | 前端场景 |
|------|------|------|---------|
| `/api/chat` | POST | 同步对话（一次请求等全部结果） | 普通问答 |
| `/api/chat/stream` | POST | **SSE 流式对话**（立即返回 + 后台分析） | 推荐主用，体验好 |
| `/api/suggested-questions` | GET | 推荐问法（16 个分析工具） | "猜你想问"按钮 |
| `/api/meta/dimensions` | GET | 分析能力目录 + 工具参数 schema + 中英字典 | 能力面板/参数表单渲染 |
| `/api/conversations` | GET | 会话列表 | 左侧会话栏 |
| `/api/conversation/history` | GET | 单个会话历史（含每轮 answer+chart） | 历史回看 |
| `/api/conversation/clear` | POST | 清空会话 | 删除按钮 |
| `/api/report` | POST | 便捷 = chat + `with_report=true` | 一键生成报告 |
| `/api/report/status` | GET | 异步报告状态轮询 | 报告生成中 |
| `/api/health` | GET | 健康检查 + 运行时统计 | 服务状态/运维 |

CORS：默认白名单 `http://localhost:3000, http://127.0.0.1:3000`（`CORS_ORIGINS` 环境变量可改）。

## 2. `/api/chat`（同步对话）

### 请求

```json
{
  "question": "不同支付方式的费用成本差是多少？",
  "with_report": false,
  "conversation_id": null,
  "use_llm_intent": true
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `question` | string | ✅ | 用户问题（中文） |
| `with_report` | bool/string | 否 | `false` 不生成报告（默认）；`true` 同步生成；`"async"` 异步生成（另查 `/api/report/status`） |
| `conversation_id` | string | 否 | 传入则启用多轮对话（不带历史）；不传每次独立 |
| `use_llm_intent` | bool | 否 | 默认 `true`（LLM 理解）；`false` 强制规则引擎（调试用） |

### 成功响应（HTTP 200，`code=0`）

```json
{
  "code": 0,
  "message": "success",
  "question": "不同支付方式的费用成本差是多少？",
  "answer": "📋 针对您的问题「不同支付方式的费用成本差是多少？」，共分析 **2,109,328** 条住院记录。\n📊 费用成本差，结果如下：\n  🥇 「Medicare」：55,992,301,462.07（846,562 例）\n  🥈 「Medicaid」：29,091,307,903.30（654,013 例）\n…",
  "chart": {
    "chart_type": "bar",
    "option": { "……": "完整 ECharts option，直接 setOption" },
    "_suggestion_source": "llm"
  },
  "intent": {
    "chart_hint": "profit_difference",
    "dimension": null,
    "metric": null,
    "filters": {},
    "_source": "langchain_agent",
    "_reasoning": "LangChain agent selected tool: profit_difference with args: …"
  },
  "meta": {
    "total_records": 2109328,
    "query_ms": 25434,
    "p4_total_ms": 25700,
    "warnings": []
  },
  "conversation_id": "xxx",
  "conversation_turn": 3,
  "report": null
}
```

### 关键字段说明

| 字段 | 说明 |
|------|------|
| `answer` | **用户看到的文本回复**（Markdown/emoji 风格）。前端无脑渲染即可，含换行 `\n` |
| `chart` | 图表配置。`option` 是**完整 ECharts option**，`chart_type` 说明图形类型 |
| `intent` | 后端解析出的意图（调试/展示用，前端一般不需要处理） |
| `meta.warnings` | 降级提示数组（如指标不支持时）；有值时前端可展示黄色提示 |
| `conversation_id` / `conversation_turn` | 多轮对话标识；前端存下 `conversation_id` 供下一轮回传 |
| `report` | `with_report=true` 时返回报告对象；`"async"` 时返回 `report_id`（见 §6） |

### chart_type 取值（对应 ECharts 图形）

| chart_type | 图形 | 出现场景 |
|-----------|------|---------|
| `bar` | 柱状图 | 排行/构成/趋势（cost 类、top 类） |
| `pie` | 饼图 | 占比类（payment composition 等） |
| `line` | 折线图 | 趋势类（legacy） |
| `scatter` | 散点图 | 费用-成本关系 |
| `sankey` | 桑基图 | 支付流向 |
| `heatmap` | 热力图 | 二维交叉 |
| `pyramid` | 金字塔图 | 人口金字塔 |

> ⚠️ `chart.option` 里可能含 `title.text/subtext`，是 LLM 生成的个性化标题，前端直接展示即可。

## 3. `/api/chat/stream`（SSE 流式对话）⭐ 推荐主用

### 请求（与 `/api/chat` 完全一致）

```
POST /api/chat/stream
Content-Type: application/json
Accept: text/event-stream
```

```json
{ "question": "不同支付方式的费用成本差是多少？", "with_report": false }
```

### 响应：`Content-Type: text/event-stream`

事件流（每块为 `event: xxx\ndata: {json}\n\n`）：

| event | data 内容 | 时机 |
|-------|----------|------|
| `start` | `{"question": "...", "ts": "2026-08-21T14:00:00"}` | 收到请求**立即**推送（前端显示"正在分析"） |
| `result` | 完整成功响应（同 §2 的 code=0 结构） | 分析完成 |
| `error` | `{code, message, answer, chart: null, meta}` | 校验失败/业务异常/超时 |
| 心跳 | `: ping`（注释行，无 data） | 每 15s 一条，防断连 |

### 前端解析示例（fetch + ReadableStream）

```js
async function chatStream(question) {
  const resp = await fetch("http://127.0.0.1:5001/api/chat/stream", {
    method: "POST",
    headers: { "Content-Type": "application/json", "Accept": "text/event-stream" },
    body: JSON.stringify({ question }),
  });
  const reader = resp.body.getReader();
  const decoder = new TextDecoder("utf-8");
  let buf = "";

  while (true) {
    const { done, value } = await reader.read();
    if (done) break;
    buf += decoder.decode(value, { stream: true });

    // SSE 块以空行分隔
    const blocks = buf.split("\n\n");
    buf = blocks.pop(); // 最后一块可能不完整，留到下一轮

    for (const block of blocks) {
      const eventLine = block.split("\n").find(l => l.startsWith("event: "));
      const dataLine = block.split("\n").find(l => l.startsWith("data: "));
      if (!eventLine || !dataLine) continue;

      const event = eventLine.slice(7).trim();
      const data = JSON.parse(dataLine.slice(6).trim());

      if (event === "start") {
        showLoading(data.question);          // 显示"正在分析…"
      } else if (event === "result") {
        renderAnswer(data.answer);           // 渲染文本
        if (data.chart) echarts.init(el).setOption(data.chart.option);
        renderWarnings(data.meta?.warnings);
        break;
      } else if (event === "error") {
        showError(data.answer || data.message);
        break;
      }
    }
  }
}
```

> 💡 若用浏览器原生 `EventSource`：它只支持 GET，而本端点需要 POST body，所以**必须用 fetch + ReadableStream**（如上）。

## 4. 错误码约定（同步 + SSE 共用）

| body.code | 含义 | 前端建议 |
|-----------|------|---------|
| `0` | 成功 | 渲染 `answer` + `chart` |
| `400` | 参数错/问题无法解析/编码丢失 | 展示 `answer`（友好话术已生成） |
| `500` | 未预期异常 | 展示 `answer`，提示稍后再试 |
| `502` | P3 分析服务连接失败 | 展示 `answer`，提示检查服务 |
| `504` | P3 响应超时 | 展示 `answer`，提示稍后重试 |

> ⚠️ 所有响应 **HTTP 状态码都是 200**，业务状态看 body 里的 `code`。
> 前端 fetch 时**不要**依赖 `resp.ok`，统一判断 `data.code === 0`。

错误响应统一形状：

```json
{
  "code": 400,
  "message": "请输入问题（question 字段不能为空）",
  "question": "",
  "answer": "⚠️ 请先输入您的问题哦~",
  "chart": null,
  "report": null,
  "meta": {}
}
```

## 6. 报告（`/api/report` 与 `/api/report/status`）

### 方式 A：同步报告

```json
POST /api/chat
{ "question": "…", "with_report": true }
```

响应里 `report` 为完整报告对象（可能较慢，几十秒）。

### 方式 B：异步报告（推荐，前端不卡）

```json
POST /api/chat
{ "question": "…", "with_report": "async" }
```

响应里返回 `report_id`（`report_pending: true, report: null`），前端轮询：

```
GET /api/report/status?report_id=rp_xxx
```

| status | 返回 |
|--------|------|
| `pending` | `{"status": "pending"}` |
| `done` | `{"status": "done", "report": {…完整报告…}}` |
| `error` | `{"status": "error", "error": "…"}` |
| 404 | `{"code": 404, "message": "report_id=xxx 不存在（或已过期）"}` |

> 报告结果在内存保留 1 小时（`ASYNC_REPORT_TTL_SECONDS`），过期需重新生成。

## 7.5 `/api/meta/dimensions`（分析能力元信息）

> 与 P3 的 `GET /api/v1/meta/dimensions`（返回诊断/术式/支付方式等**维度枚举值**）互补。
> 本端点返回 P4 的**能力目录 + 工具参数 schema + 中英字典**，全部从注册表自动聚合，
> 新增接口后自动出现，无需前端改代码。

```
GET /api/meta/dimensions
```

### 前端用途

| 字段 | 用途 |
|------|------|
| `capabilities` | 能力面板/菜单（显示有哪些分析、中文标题、预计图形）；`chart_types[0]` 可做"即将展示什么图"的图标提示 |

| `dictionaries` | 把后端英文枚举（dimension/metric）翻译成中文展示 |
| `sources` | 当前 LLM/Agent 是否可用（`langchain_agent=false` 时提示"仅规则模式"） |

> ⚠️ `capabilities[].chart_types` 是静态提示，实际渲染**以 `/api/chat` 响应里的 `chart.chart_type` 为准**。

## 10. 常见坑（前端视角）

| 坑 | 原因 | 规避 |
|----|------|------|
| 请求后收到全是 `?` 的 answer | PowerShell 5.1 编码丢失（后端已识别并提示） | 浏览器 fetch 天然 UTF-8，无此问题；仅命令行测试注意 |
| `chart.option` setOption 报错 | 某些 option 字段含 ECharts 5 特有配置 | 用项目锁定的 ECharts 版本；升级需回归 |
| 慢查询 20-30s 无反馈 | P3 聚合百万级数据 | 用 SSE 端点，前端先显示"正在分析"，等 `result` |
| SSE 收不到事件 | 代理缓冲了响应 | P4 已设 `X-Accel-Buffering: no`；本地开发直连无碍 |
