# 数据清洗完整流程说明（应对答辩/提问）

> 项目：智慧医疗大数据与AI大模型分析平台
> 数据：纽约州住院出院数据（SPARCS），2020-2024 共 5 年
> 规模：原始 ~1041 万行 → 清洗后 10,378,775 行（保留率 99.63%）

## 一、清洗流程总览

整个数据清洗分为 **4 个阶段**，对应 `scripts/` 下的 4 个脚本：

```
阶段1：CSV表头修复          fix_2024_header.py
    ↓
阶段2：CSV → MySQL 导入      clean_medical_data_final.py  (分块+断点续传)
    ↓
阶段3：数据清洗              cleaning_strict_v3.py + clean_outliers.py
    ↓
阶段4：星型模型 ETL          build_star_v4.py + build_star_v5.py
    ↓
验收：行数/5年分布/外键完整性 3 项全 PASS
```

## 二、阶段1：CSV 表头修复

**问题**：2024 年 CSV 的表头列名与其他年份不一致（如 "Health Service Area" 应为 "Hospital Service Area"、"Zip Code" 应为 "Zip Code - 3 digits"）。

**对应代码**（`fix_2024_header.py` 核心逻辑，已整合进 pipeline 阶段1）：

```python
# 2024年CSV表头映射修复
fix_map = {
    "Health Service Area": "Hospital Service Area",
    "Zip Code": "Zip Code - 3 digits",
}

with open(path, "r", encoding="utf-8", newline="") as f:
    reader = csv.reader(f, quotechar='"')
    rows = list(reader)

header = rows[0]
fixed = [fix_map.get(c.strip().strip('"'), c.strip().strip('"')) for c in header]
if fixed != header:
    shutil.copy2(path, path + ".bak")   # 备份原文件
    rows[0] = fixed                      # 修复表头
    with open(path, "w", encoding="utf-8", newline="") as f:
        writer = csv.writer(f, quotechar='"', quoting=csv.QUOTE_MINIMAL)
        writer.writerows(rows)
```

**要点**：自动检测列名不一致并修复，修复前备份 `.bak`，避免破坏原始数据。

## 三、阶段2：CSV → MySQL 批量导入（含数据清洗）

**问题**：CSV 文件单文件近 800MB，直接 `pd.read_csv` 会内存溢出。

**解决方案**：分块读取（每块 5 万行）+ 逐块清洗 + 批量写入 + 断点续传。

**对应代码**（`clean_medical_data_final.py` 核心逻辑，pipeline 阶段2）：

```python
def _clean_chunk(df):
    """清洗单个 CSV 分块"""
    df = df.copy()
    df = df.rename(columns=COLUMN_MAPPING)   # 列名映射：空格→下划线

    # 1. 字符串去空格
    for col in df.select_dtypes(include=['object']).columns:
        df[col] = df[col].astype(str).str.strip()

    # 2. 数值转换（费用字段去掉$符号）
    for col in ['Total_Charges', 'Total_Costs']:
        if col in df.columns:
            df[col] = pd.to_numeric(
                df[col].astype(str).str.replace(r'[$£€,]', '', regex=True),
                errors='coerce')

    # 3. 业务规则过滤（异常值剔除）
    df = df[(df['Total_Charges'] >= 0.01) & (df['Total_Charges'] <= 5000000)]
    df = df[(df['Length_of_Stay'] >= 0) & (df['Length_of_Stay'] <= 365)]

    # 4. 分类字段空值填 Unknown
    for col in CATEGORY_COLS:
        if col in df.columns:
            df[col] = df[col].fillna('Unknown').replace('', 'Unknown')

    # 5. 金额空值填中位数
    for col in ['Total_Charges', 'Total_Costs']:
        if col in df.columns:
            med = df[col].median()
            df[col] = df[col].fillna(med if pd.notna(med) else 0)

    return df.drop_duplicates().reset_index(drop=True)   # 6. 去重


# 分块读取 + 批量导入
for chunk in pd.read_csv(path, chunksize=50000, low_memory=False):
    cleaned = _clean_chunk(chunk)
    if len(cleaned) > 0:
        cleaned.to_sql('medical_data', con=engine, if_exists='append',
                       index=False, chunksize=500)
```

**要点**：分块防 OOM、费用去 $ 符号、业务规则过滤异常值、空值填充、分块去重、批量入库。

## 四、阶段3：数据清洗（SQL 层）

**问题**：导入后仍有少量异常记录需要 SQL 层精准清理。

**对应代码**（`cleaning_strict_v3.py` + `clean_outliers.py`，pipeline 阶段3）：

```python
# 3.1 删除异常行（4 条规则）
delete_rules = [
    ("Gender='U' 或 NULL",      "Gender='U' OR Gender IS NULL"),          # 性别未知
    ("Permanent_Facility_Id 为空", "Permanent_Facility_Id IS NULL"),      # 医院ID缺失
    ("Facility_Name 为空",       "Facility_Name IS NULL OR Facility_Name=''"),
    ("Zip_Code_3digits='nan'",   "Zip_Code_3digits='nan'"),
]
for name, cond in delete_rules:
    cur.execute(f"DELETE FROM medical_data WHERE {cond}")
    deleted = cur.rowcount
    print(f"删除 {name}: {deleted:,} 行")

# 3.2 字符串 'nan' → 真正的 NULL
nan_fields = ["Hospital_Service_Area", "CCSR_Diagnosis_Code",
              "APR_Risk_of_Mortality", "Payment_Typology_2", ...]
for field in nan_fields:
    cur.execute(f"UPDATE medical_data SET `{field}`=NULL WHERE `{field}`='nan'")
```

**关键数据**：
| 删除规则 | 行数 |
|---------|------|
| 性别 U/未知 | 1,277 |
| 医院ID缺失 | 38,050 |
| 医院名为空 | 少量 |
| **合计** | **38,680** |

**保留率**：1041万 → 1037.9万，**99.63%**。

## 五、阶段4：星型模型 ETL（2-Pass 优化）

**问题**：纯 SQL JOIN 需要 8 次全表扫描，1037 万行上极慢且易锁表。

**解决方案**：2-Pass 方案，只需 2 次全表扫描。

**对应代码**（`build_star_v4.py` 核心逻辑，pipeline 阶段4）：

```python
# Pass 1: 1次全表扫描 → 收集7个维度唯一键到 Python Set
while pos <= max_id:
    rows = conn.execute(text(f"""
        SELECT Discharge_Year, Permanent_Facility_Id, Facility_Name, ...,
               Payment_Typology_1, Payment_Typology_2, Payment_Typology_3
        FROM medical_data WHERE id BETWEEN {pos} AND {end}""")).fetchall()
    for r in rows:
        set_t.add(_k(r[0]))                                    # dim_time
        set_h.add(_k(r[1]))                                    # dim_hospital
        set_p.add((_k(r[6]),_k(r[7]),_k(r[8]),_k(r[9]),_k(r[10])))  # dim_patient
        set_d.add(_k(r[11]))                                   # dim_diagnosis
        set_pr.add(_k(r[13]))                                  # dim_procedure
        set_drg.add((_k(r[15]),_k(r[17]),_k(r[19]),_k(r[21]),_k(r[22])))  # dim_drg
        set_pay.add((_k(r[23]),_k(r[24]),_k(r[25])))           # dim_payment
    pos = end + 1

# → 批量 INSERT 7 张维度表（每批5000行）

# Pass 2: 加载 ID 字典 → 内存 O(1) 映射 → 批量 INSERT 事实表
dicts = _load_id_dicts(engine)   # 从 _etl 维表加载 ID → 字典
# 每条记录通过字典映射外键，每批500行独立commit防锁溢出
```

**关键技术决策**：
| 决策 | 原因 |
|------|------|
| 2-Pass 而非 SQL JOIN | 只扫 2 次 vs 8 次，快 4 倍 |
| 每批 500 行独立 commit | 防 MySQL 1206 锁表溢出 |
| `_etl` 临时表 + RENAME 切换 | 零锁，不阻塞线上查询 |
| dim_drg 用 5 列自然键 | 3 列键有重复，5 列键才能保证唯一 |

## 六、验收结果

```sql
-- 1. 行数对比
SELECT COUNT(*) FROM medical_data;      -- 10,378,775
SELECT COUNT(*) FROM fact_discharge;    -- 10,378,775  ✅ 一致

-- 2. 5年分布对比
SELECT w.Discharge_Year, w.cnt, f.cnt
FROM (SELECT Discharge_Year, COUNT(*) cnt FROM medical_data GROUP BY 1) w
JOIN (SELECT t.discharge_year, COUNT(*) cnt FROM fact_discharge f
      JOIN dim_time t ON f.year_id=t.year_id GROUP BY 1) f
  ON w.Discharge_Year = f.discharge_year;
-- 2020-2024 每一年 宽表=事实表  ✅

-- 3. 外键完整性（7个维度表，0孤儿）
SELECT COUNT(*) FROM fact_discharge f
LEFT JOIN dim_hospital d ON f.hospital_id=d.hospital_id
WHERE d.hospital_id IS NULL;   -- 0  ✅
```

**最终成果**：
- 事实表 `fact_discharge`：10,378,775 行
- 7 张维度表：time(5) / hospital(218) / patient(10,145) / diagnosis(485) / procedure(322) / drg(5,761) / payment(551)
- 3 项验收全 PASS：行数一致、5年分布一致、外键 7/7 无孤儿

## 七、一句话总结

> 我的数据清洗流程是：先修复CSV表头不一致，再分块读取防内存溢出地导入MySQL（期间做列名映射、数值转换、业务规则过滤、去重），然后用SQL精准删除性别未知和医院ID缺失等异常记录（共38680条，保留率99.63%），最后通过2-Pass优化构建星型模型，并用行数对比、5年分布、外键完整性三项验收保证数据不重不漏。
