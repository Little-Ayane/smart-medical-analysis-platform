## 一、核心成果一句话

对 1,000 余万条医疗原始记录完成了**清洗、标准化、建模、质检、修复**的全流程处理，最终产出 **1 张事实表 + 7 张维度表**的星型模型，数据**不重不漏**（10,378,775 行，保留率 99.63%），并通过数据质量专项检测修复了 585.8 万处占位符残留问题。

## 三、清洗流程（4 个阶段）

### 阶段 1：CSV 表头修复
自动检测并修复 2024 年 CSV 列名不一致（如 "Health Service Area" → "Hospital Service Area"），修复前自动备份 `.bak`。

### 阶段 2：CSV → MySQL 批量导入（含清洗）
- **分块读取**（每块 5 万行）防止内存溢出
- 列名映射（空格→下划线）、费用去 `$` 符号、数值类型转换
- **业务规则过滤**：费用 0.01~500 万、住院天数 0~365
- 分类字段空值填 `Unknown`、金额空值填中位数
- 分块去重、批量入库（支持断点续传）

### 阶段 3：SQL 层精准清洗
| 删除规则 | 行数 |
|---------|------|
| 性别 U/未知 | 1,277 |
| 医院 ID 缺失 | 38,050 |
| 医院名为空 | 少量 |
| **合计** | **38,680** |

### 阶段 4：星型模型 ETL（2-Pass 优化）
- **Pass 1**：1 次全表扫描收集 7 个维度唯一键 → 批量 INSERT 维表
- **Pass 2**：内存字典 O(1) 映射维度 ID → 批量 INSERT 事实表（每批 500 行独立 commit 防锁溢出）
- 用 `_etl` 临时表 + `RENAME` 原子切换，零锁不阻塞查询

## 四、本次专项质量检测与修复

### 4.1 检测范围

对 **9 张表、58 个字段**进行 7 类异常检测：常量字段、低区分度、异常符号、占位符、纯数字文本、数值异常范围、空值分布。

### 4.2 检测结论

| 检测项 | 结果 |
|--------|------|
| 常量字段（全表同值） | ✅ 未发现 |
| `=` 等异常符号 | ✅ 未发现（`dim_drg` 中的 `>` 为合法医疗术语） |
| 纯符号占位值 | ✅ 未发现 |
| **字符串 'nan' 残留** | ⚠️ **发现问题** |
| `APR_MDC_Code='0'` | ⚠️ 发现问题 |

### 4.3 问题定位

数据清洗阶段对 `'nan' → NULL` 的字段清单不完整，导致 6 个字段残留字符串 `'nan'`（而非真正的空值），共约 **585.8 万处**。其中 `CCSR_Procedure_Code` 的 291 万行属于"无手术记录"的正常业务（约 28% 病例无手术），但应存为 `NULL` 而非字符串。

### 4.4 修复执行

- **修复前备份**：`mysqldump` 导出 4.37 GB 备份文件，确保可回退
- **修复内容**：6 个宽表字段 `'nan'→NULL` + `APR_MDC_Code 0→NULL` + 9 处维度表 `'nan'→NULL`
- **修复规模**：约 585.8 万处，耗时约 11 分钟

### 4.5 修复验证

| 检查项 | 修复前 | 修复后 |
|--------|--------|--------|
| `CCSR_Procedure_Code='nan'` | 2,919,916 | **0** ✅ |
| `CCSR_Diagnosis_Code='nan'` | 1,628 | **0** ✅ |
| `APR_MDC_Code=0` | 3,028 | **0** ✅ |
| 维度表含 'nan' | 124 | **0** ✅ |
| **总行数** | 10,378,775 | **10,378,775** ✅ 不变 |

## 六、主要问题与经验（可答辩引用）

| 问题 | 处理 | 经验 |
|------|------|------|
| 数据重复插入（2000 万条） | TRUNCATE 重新导入 | 入库脚本必须幂等 |
| MySQL 锁表溢出 | 每批 500 行独立 commit | 大数据写入小批量更稳 |
| dim_drg 唯一键冲突 | 3 列键改 5 列自然键 | 维度键要用数据验证区分度 |
| 'nan' 字符串残留 | 补齐字段清单修复 | 清洗规则要覆盖全部相关字段 |
| 纯 SQL ETL 太慢 | 2-Pass 优化 | 减少全表扫描次数 |

## 七、结论

本次数据清洗工作完成了从原始 CSV 到星型模型的完整链路，数据质量达到分析可用标准。在质量专项检测中发现并修复了历史清洗遗漏的 `'nan'` 占位符问题（585.8 万处），修复后数据语义更准确、查询判断更可靠，总数据量保持不变，为后端分析接口和 AI 模型提供了干净、规范、不重不漏的数据基础。
