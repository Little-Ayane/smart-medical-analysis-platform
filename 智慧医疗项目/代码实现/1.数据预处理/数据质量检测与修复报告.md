# 数据质量检测与修复报告

> 项目：智慧医疗大数据与AI大模型分析平台
> 数据表：`medical_db.medical_data`（宽表）+ 7 张维度表 + 事实表
> 数据规模：10,378,775 行 / 34 字段
> 检测时间：2026-08-24
> 执行人：骆志远

---

## 一、检测背景

团队在项目协作中发现部分字段值疑似存在异常（如 `=`、`-` 等特殊字符、病种字段空数据），要求对整体数据质量进行系统性核查，重点排查：
1. 常量字段（全表所有记录值相同，零信息量）
2. 低区分度字段（唯一值极少）
3. 值含异常符号（`=`、`?`、`#`、`*`、`%`、`<`、`>`、`&`、制表符、换行等）
4. 占位符/垃圾值（`nan`、`None`、`NULL`、`N/A`、`Unknown`、纯减号等）
5. 文本字段出现纯数字/下划线
6. 数值字段异常范围
7. 空值分布（高缺失率字段）

---

## 二、检测方法

### 2.1 检测范围

| 表 | 说明 |
|----|------|
| `medical_data` | 宽表（10,378,775 行，34 字段） |
| `fact_discharge` | 事实表（10,378,775 行，15 字段） |
| `dim_time` / `dim_hospital` / `dim_patient` | 维度表 |
| `dim_diagnosis` / `dim_procedure` | 病种维度表 |
| `dim_drg` / `dim_payment` | DRG/支付维度表 |

### 2.2 检测手段

- `COUNT(DISTINCT col)`：检测常量字段与低区分度字段
- `LIKE` / `REGEXP`：检测异常符号与纯符号值
- 占位符枚举：`nan / n/a / none / null / unknown / -1 / 0 / . / ?` 等
- 数值范围校验：住院天数 0-365、费用 0.01-500万、出生体重 0-8000g 等
- 空值统计：`IS NULL OR =''`

| `APR_Medical_Surgical_Description` | 3 | Medical/Surgical/Not Applicable | ✅ 正常（内科/外科/不适用） |

### 3.2 异常符号检测

**结论：除 DRG 描述中的 `>` 外，未发现 `=`、`?`、`#`、`*` 等异常符号。**

| 位置 | 值样例 | 数量 | 判定 |
|------|--------|------|------|
| `dim_drg.apr_drg_description` | `TRACHEOSTOMY WITH MV >96 HOURS` | 177（占3.1%） | ✅ **正常**——`>` 是医疗术语标准写法，表示"超过"（机械通气>96小时、昏迷>1小时等），非脏数据 |

### 3.3 占位符/垃圾值检测（核心问题）

**发现大量字符串 `'nan'` 残留，未转换为真正的 NULL。**

#### medical_data 宽表

| 字段 | 'nan'/异常值数量 | 占比 | 问题等级 |

| `CCSR_Diagnosis_Code` | 1,628 | 0.02% | 低 |
| `CCSR_Diagnosis_Description` | 1,628 | 0.02% | 低 |
| `APR_Severity_of_Illness_Description` | 3,768 | 0.04% | 低 |
| `APR_Risk_of_Mortality` | 3,768 | 0.04% | 低 |
| `APR_MDC_Code` | 3,028（值为'0'） | 0.03% | 低 |

#### 维度表

| 表 | 字段 | 'nan'数量 |
|----|------|----------|
| `dim_diagnosis` | ccsr_diagnosis_code / _description | 各 1 |
| `dim_procedure` | ccsr_procedure_code / _description | 各 1 |
| `dim_drg` | apr_severity_description | 3 |
| `dim_drg` | apr_risk_of_mortality | 3 |
| `dim_payment` | payment_typology_1 | 8 |
| `dim_payment` | payment_typology_2 | 13 |
| `dim_payment` | payment_typology_3 | 94 |

### 3.4 数据语义说明

`CCSR_Procedure_Code` 的 291 万行 `'nan'` 属于**业务语义正常**：SPARCS 原始数据中约 28% 的住院病例**无手术记录**，这些记录的手术相关字段本应为空。清洗阶段应将其转为 `NULL`，但实际残留为字符串 `'nan'`，造成：
- 语义不准确（`'nan'` 是字符串而非空值）
- 影响查询判断（`WHERE procedure_code = 'nan'` 与 `IS NULL` 语义混淆）

## 四、修复方案与执行

### 4.1 安全措施

修复前先对 `medical_data` 全表执行 `mysqldump` 备份：

```
备份文件: scripts/backup_medical_data_before_fix.sql
备份大小: 4.37 GB
```

### 4.2 修复 SQL

```sql
-- 1. medical_data 宽表：'nan' 字符串 → NULL
UPDATE medical_data SET CCSR_Diagnosis_Code = NULL WHERE CCSR_Diagnosis_Code = 'nan';
UPDATE medical_data SET CCSR_Diagnosis_Description = NULL WHERE CCSR_Diagnosis_Description = 'nan';
UPDATE medical_data SET CCSR_Procedure_Code = NULL WHERE CCSR_Procedure_Code = 'nan';
UPDATE medical_data SET CCSR_Procedure_Description = NULL WHERE CCSR_Procedure_Description = 'nan';
UPDATE medical_data SET APR_Severity_of_Illness_Description = NULL WHERE APR_Severity_of_Illness_Description = 'nan';
UPDATE medical_data SET APR_Risk_of_Mortality = NULL WHERE APR_Risk_of_Mortality = 'nan';
UPDATE medical_data SET APR_MDC_Code = NULL WHERE APR_MDC_Code = 0;

-- 2. 维度表：'nan' → NULL
UPDATE dim_diagnosis SET ccsr_diagnosis_code = NULL WHERE ccsr_diagnosis_code = 'nan';
UPDATE dim_diagnosis SET ccsr_diagnosis_description = NULL WHERE ccsr_diagnosis_description = 'nan';
UPDATE dim_procedure SET ccsr_procedure_code = NULL WHERE ccsr_procedure_code = 'nan';
UPDATE dim_procedure SET ccsr_procedure_description = NULL WHERE ccsr_procedure_description = 'nan';
UPDATE dim_drg SET apr_severity_description = NULL WHERE apr_severity_description = 'nan';
UPDATE dim_drg SET apr_risk_of_mortality = NULL WHERE apr_risk_of_mortality = 'nan';
UPDATE dim_payment SET payment_typology_1 = NULL WHERE payment_typology_1 = 'nan';
UPDATE dim_payment SET payment_typology_2 = NULL WHERE payment_typology_2 = 'nan';
UPDATE dim_payment SET payment_typology_3 = NULL WHERE payment_typology_3 = 'nan';
```

## 六、后续建议

1. **清洗脚本补漏**：`clean_medical_data_final.py` 的 `nan_fields` 清单应补充 `CCSR_Procedure_Code`、`CCSR_Procedure_Description`、`APR_Severity_of_Illness_Code/Description`、`APR_Risk_of_Mortality` 等字段，避免后续重跑再次残留 'nan'。
2. **接口语义统一**：后端接口如需过滤"无手术病例"，应统一使用 `procedure_id IS NULL`，而非 `= 'nan'`。
3. **Hive 数据同步**：若 Hive ODS 层数据与 MySQL 同源，建议同步检查并修复 Hive 中的 'nan' 残留。
4. **定期质检**：建议在数据流水线中增加数据质量检测步骤，自动扫描占位符/异常符号/常量字段。
