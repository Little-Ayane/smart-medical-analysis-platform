# 病种与手术分析 + 支付分析 —— RESTful API 接口文档

> 版本：v1.0 | 服务框架：Flask | 基础路径：`/api/v1` | 数据格式：JSON（UTF-8）
> 适用范围：智慧医疗大数据分析平台 · 病种与手术分析、支付分析 两大模块（共 14 个接口）
> 关联文档：`RESTful_API接口文档.md`（通用聚合/AI 交互模块接口，本模块不改变其任何行为）

## 一、概述

| 模块 | 前缀 | 功能 | 前端图表 |
| --- | --- | --- | --- |
| 病种与手术分析 | `/api/v1/disease/` | Top诊断排行、病重趋势、人群差异、地区差异、手术谱、热力图 | 柱状图、词云、堆叠柱、折线、人口金字塔、热力图 |

## 二、通用约定

### 2.1 统一响应信封（在既有规范上扩展，只增不改）

```json
{
  "code": 0,
  "message": "success",
  "data": { },
  "meta": {
    "dimension": "ccsr_diagnosis",
    "metric": "count",
    "total_records": 2055140,
    "filters": { "gender": "F" },
    "cached": false,
    "query_ms": 737,
    "generated_at": "2026-08-17T10:00:00"
  }
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `code` | int | 0 成功；400 参数错误；500 内部错误（HTTP 状态码恒为 200，错误看 `code`） |
| `data` | object/array | 结构化分析结果，可直接喂给 ECharts |
| `meta.dimension` | string | 本次查询维度（热力图/交叉为 `dim1_x_dim2` 形态） |
| `meta.metric` | string | 本次查询指标 |
| `meta.total_records` | int | 参与计算的总记录数（各端点口径见第三节） |
| `meta.filters` | object | **新增**：规范化后的过滤条件回显（供前端"当前筛选"展示） |
| `meta.cached` | bool | **新增**：是否命中进程内缓存（true 时 `query_ms=0`） |
| `meta.query_ms` | int | 查询耗时（毫秒） |
| `meta.null_excluded` / `meta.levels` / `meta.top` | — | 端点级附加字段，见各端点说明 |

### 2.2 统一过滤参数（所有端点通用，全部白名单 + 参数化）

所有端点均接受以下过滤参数（可叠加，AND 关系）。参数名不在白名单的一律忽略，**值非法返回 400**：

| 参数 | 取值 | 说明 |
| --- | --- | --- |
| `year` | `2021` | 出院年份。**当前数据仅 2021 年**，传其他值返回 400 |
| `gender` | `M` / `F` | 性别 |
| `age_group` | `0 to 17` 等 5 档 | 年龄段（精确匹配） |
| `payment` / `payment2` / `payment3` | `Medicare` 等 9 类 | 第一/二/三支付方式 |
| `severity` | `1`-`4` 或 `Minor/Moderate/Major/Extreme` | 病情严重程度（代码或名称，不区分大小写） |
| `diagnosis` | CCSR 代码（如 `INF012`）或描述（如 `SEPTICEMIA`） | 病种，先按代码精确匹配，再按描述匹配 |
| `procedure` | 同上（如 `PGN003`） | 手术 CCSR |
| `service_area` | `New York City` 等 8 区 | 医院服务区域 |
| `county` | `Manhattan` 等 57 县 | 医院所在县 |
| `facility` | 医院全名（如 `Strong Memorial Hospital`） | 精确匹配 |

示例：`GET /api/v1/disease/top-diagnoses?top=10&gender=F&age_group=70 or Older`

### 2.3 错误码

| code | 说明 | 示例响应 |
| --- | --- | --- |
| 400 | 参数非法（message 会说明允许的取值） | `{"code":400,"message":"metric 仅支持 [...]，收到: evil","data":null,"meta":{}}` |
| 500 | 服务内部错误（message 为通用文案，明细在后端日志） | — |

### 2.4 CORS 与缓存

- 已开启 CORS（`Access-Control-Allow-Origin: *`），前端可跨域直连。
- **进程内 TTL 缓存 1 小时**（`meta.cached` 标识；数据为静态单年快照，重复请求近乎零延迟）。
- 服务必须单进程运行：`python app.py`（已默认 `debug=False`）；不要用 `debug=True`（reloader 双进程会让缓存失效一半）。

## 三、数据口径声明（前端文案/图例必须对齐，重要）

1. **单年数据**：`discharge_year` 仅有 2021 年。不存在时间趋势类图表；"病重趋势"接口以**分组 × 严重程度构成**为形态（`severity-profile`）。
2. **手术谱口径**：事实表 556,348 条（27%）无手术记录，手术类接口只统计 `procedure_id` 非空的 1,500,426 条（`meta.total_records` 会体现）。
3. **诊断口径**：1,634 条无诊断记录不参与诊断排行（total = 2,055,140）。
4. **Self-Pay 双口径**（`oop-burden` 的 `mode` 参数）：
   - `selfpay1`：第一支付方式为 Self-Pay（全额自费，26,310 条），**有真实费用**，返回金额字段；
   - `any_layer`：任一支付层含 Self-Pay（约 33 万条），**无真实自付金额**（本数据无法推断保险剩余部分），只返回占比字段。
5. **NULL 映射**：`apr_severity_desc` 空 2,543 条、`gender` 空 151 条统一映射为 `Unknown` 组；金字塔排除 gender 空值（total = 2,056,623）。
6. **地区无归属**：`facility_id` 为空 12,089 条在地区类接口中归入 `Unknown` 组。
7. **heatmap/cross 的 top 语义**：`top` 取的是**全局频次前 N** 的病种/手术（与当前过滤条件无关），保证切换筛选时排行稳定、不跳动。

## 四、模块一：病种与手术分析 `/api/v1/disease/`

### 4.1 Top 诊断排行 `GET /disease/top-diagnoses`

柱状图（`name` 为 X 轴、`value` 为 Y 轴）；词云（`name` 为词、`count` 为字号权重）。

| 参数 | 说明 |
| --- | --- |
| `metric` | `count`（默认）/ `total_charges` / `avg_charges` / `avg_los` |
| `top` | 返回条数，默认 20，上限 100 |
| 2.2 全部过滤参数 | |

```json
GET /api/v1/disease/top-diagnoses?metric=count&top=3
{
  "data": [
    { "code": "PNL001", "name": "LIVEBORN", "count": 154598, "value": 154598 },
    { "code": "INF002", "name": "SEPTICEMIA", "count": 138031, "value": 138031 },
    { "code": "INF012", "name": "CORONAVIRUS DISEASE 2019 (COVID-19)", "count": 82591, "value": 82591 }
  ],
  "meta": { "dimension": "ccsr_diagnosis", "metric": "count", "total_records": 2055140, "filters": {}, "cached": false, "query_ms": 737 }
}
```

### 4.2 手术谱排行 `GET /disease/top-procedures`

柱状图。参数同 4.1（`metric` 支持 `count` / `total_charges` / `avg_charges`）。
口径：仅手术记录 1,500,426 条（`meta.total_records`）。

```json
{ "data": [ { "code": "PGN002", "name": "SPONTANEOUS VAGINAL DELIVERY", "count": 113319, "value": 113319 }, ... ] }
```

### 4.3 病重趋势 `GET /disease/severity-profile`

堆叠柱状图：X 轴 = `group`，系列 = `severity`，值为 `value`（可选百分比堆叠用 `count` 自行换算）。

| 参数 | 说明 |
| --- | --- |
| `by` | 分组维度：`age_group`（默认）/ `medical_surgical` / `payment` |
| `metric` | `count`（默认）/ `avg_charges` |

```json
GET /api/v1/disease/severity-profile?by=age_group
{
  "data": [
    { "group": "0 to 17", "severity": "Minor", "value": 135802, "count": 135802 },
    { "group": "0 to 17", "severity": "Moderate", "value": 70471, "count": 70471 },
    { "group": "70 or Older", "severity": "Extreme", "value": 120187, "count": 120187 }
  ],
  "meta": { "dimension": "severity_profile", "metric": "count", "total_records": 2056774 }
}
```

`severity` 顺序固定：Minor < Moderate < Major < Extreme < Unknown（含 2,543 条空值记录）。

### 4.4 人群差异 `GET /disease/population-diff`

分组柱状图：X 轴 = `key`，Y 轴 = `value`（`pct` 用于占比标签）。

| 参数 | 说明 |
| --- | --- |
| `dimension` | `gender`（默认）/ `race` / `medical_surgical` |
| `metric` | `count`（默认）/ `avg_charges` / `avg_los` |

```json
{ "data": [
  { "key": "F", "count": 1119640, "pct": 54.44, "value": 1119640 },
  { "key": "M", "count": 936983, "pct": 45.56, "value": 936983 },
  { "key": "Unknown", "count": 151, "pct": 0.01, "value": 151 } ] }
```

### 4.5 人口金字塔 `GET /disease/pyramid`

专用结构，前端直接用 ECharts 双向条形图：男为负值向左、女为正值向右。

```json
{ "data": [
  { "age_group": "0 to 17", "male": 129502, "female": 115576, "total": 245078 },
  { "age_group": "70 or Older", "male": 279957, "female": 339616, "total": 619573 } ],
  "meta": { "dimension": "age_group_gender", "metric": "count", "total_records": 2056623 } }
```

口径：排除 gender 空值 151 条；行顺序固定按年龄段升序。

### 4.6 地区差异 `GET /disease/region-diff`

柱状图（`key`/`value`）；地区地图（service_area 层可直接对应纽约州区域图）。

| 参数 | 说明 |
| --- | --- |
| `level` | `service_area`（默认，8 区全量 + Unknown 组）/ `county`（57 县 + Unknown）/ `facility`（210 家医院） |
| `metric` | `count`（默认）/ `total_charges` / `avg_charges` |
| `top` | 默认：service_area 20 / county 20 / **facility 15**（医院名长，前端请旋转轴标签），上限 50 |

```json
GET /api/v1/disease/region-diff?level=service_area
{ "data": [
  { "key": "New York City", "count": 913496, "value": 913496 },
  { "key": "Long Island", "count": 331353, "value": 331353 } ] }
```

### 4.7 通用热力图 `GET /disease/heatmap`

ECharts heatmap 长表格式：`[dim1, dim2, value]` 三元组（附 `count` 与名称列）。

| 参数 | 说明 |
| --- | --- |
| `dim1` / `dim2` | 白名单：`diagnosis` / `procedure` / `age_group` / `severity` / `gender` / `payment` / `service_area`（两者不能相同） |
| `metric` | `count`（默认）/ `avg_charges` / `avg_los` |
| `top` | diagnosis/procedure 维度取全局前 N（默认 15，上限 50），其余维度全量 |

```json
GET /api/v1/disease/heatmap?dim1=diagnosis&dim2=age_group&top=5
{ "data": [
  { "dim1": "PNL001", "dim1_name": "LIVEBORN", "dim2": "0 to 17", "dim2_name": "0 to 17",
    "count": 154598, "value": 154598 } ],
  "meta": { "dimension": "diagnosis_x_age_group", "top": 5, "total_records": 2056774 } }
```

## 五、模块二：支付分析 `/api/v1/payment/`

### 5.1 支付构成 `GET /payment/composition`

饼图：`key` 为扇区名，`pct` 为百分比（按所选 `metric` 口径），`value` 为数值。

| 参数 | 说明 |
| --- | --- |
| `group` | `payment1`（默认）/ `payment2` / `payment3` |
| `metric` | `count`（默认）/ `total_charges` |

```json
GET /api/v1/payment/composition?group=payment2
{ "data": [
  { "key": "Medicaid", "count": 407960, "pct": 40.27, "value": 407960 },
  { "key": "Self-Pay", "count": 153374, "pct": 15.14, "value": 153374 } ],
  "meta": { "dimension": "payment2", "metric": "count", "total_records": 2056774,
            "null_excluded": 1043819 } }
```

口径：该支付层为 NULL 的记录不计入构成，`meta.null_excluded` 为排除数（payment2 = 1,043,819）；`pct` 按排除后总数计算。前端文案示例："仅显示有次要支付方式的记录（占全部 49.2%）"。

### 5.2 支付交叉 `GET /payment/cross`

堆叠柱：X 轴 = `key`（9 类支付方式），系列 = `dim2`，值为 `value`；也可直接换热力。

| 参数 | 说明 |
| --- | --- |
| `dim2` | `age_group`（默认）/ `diagnosis` / `severity` |
| `metric` | `count`（默认）/ `total_charges` |
| `top` | dim2=diagnosis 时取全局前 N（默认 15） |

```json
{ "data": [
  { "key": "Medicare", "dim2": "70 or Older", "dim2_name": "70 or Older", "count": 524788, "value": 524788 } ] }
```

### 5.3 桑葚图 `GET /payment/sankey`

ECharts sankey 直接消费 `nodes` / `links`（`display` 为展示名，`layer`/`layer_index` 用于分层着色）。

| 参数 | 说明 |
| --- | --- |
| `levels` | 硬编码白名单（见下），默认 `payment,payment2` |
| `top_disease` | 病种层取全局前 N（默认 8，上限 20） |

`levels` 白名单（禁止自由组合）：

| levels | 链路 | 样本规模 |
| --- | --- | --- |
| `payment,payment2` | 支付1 → 支付2 | 1,012,955 |
| `payment,payment2,payment3` | 支付1 → 支付2 → 支付3 | 326,038 |
| `payment,age_group` | 支付 → 年龄段 | 2,056,774 |
| `payment,age_group,disease` | 支付 → 年龄段 → 病种 | 2,055,140 |
| `payment,disease` | 支付 → 病种 | 2,055,140 |
| `payment,severity` | 支付 → 严重程度 | 2,054,231 |

```json
GET /api/v1/payment/sankey?levels=payment,payment2
{
  "data": {
    "nodes": [
      { "name": "支付1|Medicare", "display": "Medicare", "layer": "支付1", "layer_index": 0 },
      { "name": "支付2|Medicaid", "display": "Medicaid", "layer": "支付2", "layer_index": 1 }
    ],
    "links": [ { "source": "支付1|Medicare", "target": "支付2|Medicaid", "value": 201825 } ]
  },
  "meta": { "dimension": "sankey", "metric": "count", "total_records": 1012955,
            "null_excluded": 1043819, "levels": "payment,payment2" }
}
```

约定：
- **节点 `name` 一律带层前缀**（如 `支付1|Medicare`），因为同一支付方式会出现在多层，ECharts sankey 要求节点名全局唯一；展示用 `display`。
- `total_records` = 走完全部层级的记录数；`null_excluded` = 因中间层为空而退出链路的记录数。
- 三级链只有 15.8% 的记录能走完，前端建议提示"仅统计三支付方式齐全的记录"。

### 5.4 支付费用关系 `GET /payment/cost-relation`

散点图：X = `avg_costs`，Y = `avg_charges`，气泡大小 = `count`，**颜色编码 `charge_cost_ratio`**（费用/成本比，二者强线性相关，用比率偏离中位数着色才有信息量）。

| 参数 | 说明 |
| --- | --- |
| `by` | `payment`（默认）/ `diagnosis` / `age_group` |
| `top` | by=diagnosis 时取全局前 N（默认 30，上限 100） |

```json
{ "data": [
  { "key": "Medicare", "count": 826128, "avg_charges": 87986.26,
    "avg_costs": 25755.28, "charge_cost_ratio": 3.42 } ] }
```

### 5.5 自付负担 `GET /payment/oop-burden`

柱状/散点：X = `key`，Y = `self_pay_pct` 或 `self_pay_count`；散点可做 `self_pay_pct` × `self_pay_avg_charges`。

| 参数 | 说明 |
| --- | --- |
| `dimension` | `disease`（默认）/ `age_group` / `county` |
| `mode` | `selfpay1`（默认，全额自费，有金额）/ `any_layer`（任一层含 Self-Pay，仅占比） |
| `top` | dimension=disease 时取全局前 N（默认 15） |

```json
GET /api/v1/payment/oop-burden?dimension=age_group&mode=selfpay1
{ "data": [
  { "key": "30 to 49", "total_count": 415627, "self_pay_count": 7218, "self_pay_pct": 1.74,
    "self_pay_charges": 353032640.52, "self_pay_avg_charges": 48910.04,
    "self_pay_share_of_charges": 1.44 } ] }
```

> 返回按 `self_pay_count` 降序（负担最重的组排前），前端如需按年龄段/县名自然排序请自行用 `key` 重排。

| 字段 | 说明 | 仅哪个 mode |
| --- | --- | --- |
| `self_pay_pct` | 自付记录占比（%） | 两个 mode |
| `self_pay_charges` | 自付人群费用合计 | selfpay1 |
| `self_pay_avg_charges` | 自付人群次均费用 | selfpay1 |
| `self_pay_share_of_charges` | 自付费用占该组总费用比例（%） | selfpay1 |

> **口径边界**：`any_layer` 模式下**不要**渲染"人均自付额"——本数据无法推断保险报销后的自付金额，只能给占比。

### 5.6 KPI 总览 `GET /payment/summary`

大屏首页卡片，无参数（仅支持 2.2 过滤参数）。

```json
{ "data": {
  "total_records": 2056774,
  "total_charges": 153555627951.47, "total_costs": 46095406196.02,
  "avg_charges": 74658.48, "avg_costs": 22411.51, "avg_los": 5.83,
  "self_pay_count": 26310, "self_pay_pct": 1.28,
  "top_payment": { "key": "Medicare", "count": 826128, "pct": 40.17 },
  "severity_distribution": { "Minor": 598786, "Moderate": 755709,
                             "Major": 498975, "Extreme": 200761, "Unknown": 2543 },
  "ed_count": 1316133 } }
```

## 七、索引清单（DBA/P2 参考）

本模块上线前已对 `fact_inpatient_discharge` 追加两条覆盖索引（`schema.sql` 已同步）：

```sql
ALTER TABLE fact_inpatient_discharge
  ADD KEY idx_pay1_pay2 (payment_typology_1, payment_typology_2),   -- 支付交叉/桑葚图
  ADD KEY idx_age_gender (age_group, gender);                       -- 人口金字塔/人群差异
```

- 验证：`EXPLAIN SELECT payment_typology_1, payment_typology_2, COUNT(*) FROM fact_inpatient_discharge GROUP BY 1,2` 应出现 `Using index`。
- 注意：**不要**使用前缀索引（如 `payment_typology_2(16)`），前缀索引无法服务 GROUP BY。
- 可选优化（未执行）：`KEY idx_payment_3 (payment_typology_3)`、`KEY idx_gender (gender)`（性别过滤目前全表扫描，首次查询约 15s，命中缓存后为 0ms）。
