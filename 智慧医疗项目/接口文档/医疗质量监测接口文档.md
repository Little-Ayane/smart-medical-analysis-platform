## 二、通用约定（与本服务其它模块一致）

### 2.1 统一响应信封

```json
{
  "code": 0,
  "message": "success",
  "data": { },
  "meta": {
    "dimension": "quality_overview",
    "metric": "kpi",
    "total_records": 2056774,
    "filters": { "gender": "F" },
    "cached": false,
    "query_ms": 832,
    "generated_at": "2026-08-21T09:30:00"
  }
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `code` | int | 0 成功；400 参数错误；500 内部错误（HTTP 状态码恒为 200，错误看 `code`） |
| `data` | object/array | 结构化分析结果（本模块：`overview` 返回对象，其余 4 个返回数组） |
| `meta.dimension` | string | 本次查询维度标识（如 `quality_mortality_diagnosis`） |
| `meta.metric` | string | 本次查询指标（`kpi` / `mortality_rate` / `avg_los` / `count`） |
| `meta.total_records` | int | 当前过滤口径下参与计算的总出院记录数 |
| `meta.filters` | object | 规范化后的过滤条件回显（供前端"当前筛选"展示） |
| `meta.cached` | bool | 是否命中进程内缓存（true 时 `query_ms=0`） |
| `meta.query_ms` | int | 查询耗时（毫秒） |

### 2.2 统一过滤参数（所有端点通用，全部白名单 + 参数化）

与病种/支付模块共用 `common.py` 的 `parse_filters`，支持同一组过滤参数（可叠加，AND 关系）。参数名不在白名单的一律忽略，**值非法返回 400**：

| 参数 | 取值 | 说明 |
| --- | --- | --- |
| `year` | `2021` | 出院年份。**当前数据仅 2021 年**，传其他值返回 400 |
| `gender` | `M` / `F` | 性别 |
| `age_group` | `0 to 17` 等 5 档 | 年龄段（精确匹配） |
| `payment` / `payment2` / `payment3` | `Medicare` 等 9 类 | 第一/二/三支付方式 |
| `severity` | `1`-`4` 或 `Minor/Moderate/Major/Extreme` | 病情严重程度（按 `apr_severity_code` 匹配） |
| `diagnosis` | CCSR 代码（如 `INF012`）或描述（如 `SEPTICEMIA`） | 病种，先按代码精确匹配，再按描述匹配 |
| `procedure` | 同上（如 `PGN003`） | 手术 CCSR |
| `service_area` | `New York City` 等 8 区 | 医院服务区域 |
| `county` | `Manhattan` 等 57 县 | 医院所在县 |
| `facility` | 医院全名（如 `Strong Memorial Hospital`） | 精确匹配 |

示例：`GET /api/v1/quality/mortality?dimension=facility&top=10&gender=F&min_cases=50`

### 2.3 错误码

| code | 说明 | 示例响应 |
| --- | --- | --- |
| 400 | 参数非法（message 会说明允许的取值） | `{"code":400,"message":"dimension 仅支持 [...], 收到: evil","data":null,"meta":{}}` |
| 500 | 服务内部错误（message 为通用文案，明细在后端日志） | — |

本模块通过 `_shared.py` 的 `_endpoint` 统一包装：`BadRequest` → 400，其余异常 → 500。

### 2.4 CORS 与缓存

- 已开启 CORS（`Access-Control-Allow-Origin: *`），前端可跨域直连。
- **进程内 TTL 缓存 1 小时**（`meta.cached` 标识；数据为静态单年快照）。
- 服务必须单进程运行：`python app.py`（已默认 `debug=False`）。

## 三、数据口径声明（前端文案/图例必须对齐，重要）

> 数据为 NY SPARCS 2021 快照，字段见《数据库设计》schema.sql。口径统一在 `modules/quality/_shared.py` 以 SQL 条件常量定义，多接口复用。

1. **住院死亡率**：`patient_disposition` 含 `Expired` 的记录占比（院内死亡）。
2. **非医嘱离院率（AMA）**：`patient_disposition` 含 `Left Against Medical Advice`。
3. **转院率**：离院去向为短期综合医院（Short-Term General Hospital）/ 联邦医疗机构（Fed Health Care）/ 乡村急救医院（Inpatient Critical Access）。
4. **低出生体重率**：`birth_weight < 2500` 克；**仅新生儿有出生体重**，非新生儿为 NULL、不参与分母（`newborns` = 有出生体重记录数）。
5. **不提供的指标**：再入院率（数据无患者唯一标识，无法跨次住院关联同一患者）、院内感染率（数据无感染相关字段）——本平台一律不提供。
6. **`min_cases` 语义**：最小样本量阈值，剔除分母过小导致比率失真的分组（`HAVING cnt >= min_cases`）。取值范围 `[1, 10000]`。
7. **`dimension=risk_mortality`**：按预期死亡风险（APR-DRG `apr_risk_mortality`）分层的**观察死亡率**，作为风险调整对照视图使用——并非"某风险层的预期死亡率"本身。
8. **地区/医院无归属**：`facility_id` 为空 12,089 条在 `facility` 维度 / `facility-ranking` 中归入 `Unknown` 组（与 region-diff 口径一致）。
9. **比率精度**：所有百分比统一保留 2 位小数，由 Python 侧计算（除 `overview` 用 SQL `SUM`/`AVG` 外，`facility-ranking` 的比率全部在 post 阶段计算，确保分母统一）。
10. **排序语义**：`mortality`/`length-of-stay` 按指标值降序、`facility-ranking` 按出院量 `count` 降序后截断 `top` 条——排行与当前过滤条件相关，非全局固定。

## 四、模块四：医疗质量监测 `/api/v1/quality/`

### 4.0 维度映射（`mortality` / `length-of-stay` 的 `dimension` 参数）

| dimension | 分组依据 | `key` | `name` | 附加字段 |
| --- | --- | --- | --- | --- |
| `diagnosis`（默认） | `f.diagnosis_id` → `dim_ccsr_diagnosis` | `ccsr_code`（如 `INF002`） | `description`（如 `SEPTICEMIA`） | — |
| `facility` | `f.facility_id` → `dim_facility` | `facility_name` | `facility_name` | `county`（`hospital_county`） |
| `age_group` | `f.age_group` | 同 `name` | 年龄段（`0 to 17` 等 5 档） | — |
| `severity` | `f.apr_severity_desc` | 同 `name` | `Minor`/`Moderate`/`Major`/`Extreme`（空值归 `Unknown`） | — |
| `risk_mortality` | `f.apr_risk_mortality` | 同 `name` | 预期死亡风险分层原值（风险调整对照） | — |

> 注意：`dimension=severity` 用的是**严重程度描述** `apr_severity_desc`（Minor/Moderate/Major/Extreme），与 2.2 过滤参数 `severity` 用代码 `apr_severity_code`（1-4）是**两列不同的字段**，勿混用。

### 4.1 质量 KPI 总览 `GET /quality/overview`

大屏首页卡片：一条 SQL 一次算出全部质量 KPI。**无额外参数**（仅支持 2.2 通用过滤）。

```json
GET /api/v1/quality/overview
{
  "data": {
    "total_records": 2056774,
    "deaths": 12345,
    "mortality_rate": 0.60,
    "avg_los": 5.83,
    "ed_count": 1316133,
    "ed_rate": 63.99,
    "ama_count": 2468,
    "ama_rate": 0.12,
    "transfer_count": 5700,
    "transfer_rate": 0.28,
    "newborns": 245078,
    "lbw_count": 1985,
    "lbw_rate": 0.81,
    "avg_charges": 74658.48,
    "avg_costs": 22411.51
  },
  "meta": { "dimension": "quality_overview", "metric": "kpi", "total_records": 2056774 }
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `total_records` | int | 总出院记录数（当前过滤口径） |
| `deaths` | int | 院内死亡数（`Expired`） |
| `mortality_rate` | float | 死亡率（%）= `deaths / total_records × 100` |
| `avg_los` | float | 平均住院日（天）= `AVG(length_of_stay)` |
| `ed_count` | int | 急诊入院数（`ed_indicator = 'Y'`） |
| `ed_rate` | float | 急诊入院率（%） |
| `ama_count` | int | 非医嘱离院数 |
| `ama_rate` | float | 非医嘱离院率（%） |
| `transfer_count` | int | 转院数 |
| `transfer_rate` | float | 转院率（%） |
| `newborns` | int | 有出生体重记录数（`birth_weight IS NOT NULL`） |
| `lbw_count` | int | 低出生体重数（`<2500g`） |
| `lbw_rate` | float \| null | 低出生体重率（%）= `lbw_count / newborns × 100`；`newborns=0` 时为 `null` |
| `avg_charges` | float | 次均费用 |
| `avg_costs` | float | 次均成本 |

> 前端注意：`lbw_rate` 的分母是 `newborns`（有出生体重的记录），而非 `total_records`。

### 4.5 离院去向构成 `GET /quality/disposition`

饼图：`key` 为扇区名，`pct` 为百分比，`count` 为数值。**无额外参数**（仅支持 2.2 通用过滤）。

```json
GET /api/v1/quality/disposition
{
  "data": [
    { "key": "Home", "count": 1520010, "pct": 73.90 },
    { "key": "Transfer/Other Facility", "count": 180520, "pct": 8.78 },
    { "key": "SNF", "count": 140010, "pct": 6.81 },
    { "key": "Hospice", "count": 60120, "pct": 2.92 },
    { "key": "Expired", "count": 43180, "pct": 2.10 },
    { "key": "AMA", "count": 21050, "pct": 1.02 },
    { "key": "Other", "count": 91884, "pct": 4.47 }
  ],
  "meta": { "dimension": "disposition", "metric": "count", "total_records": 2056774 }
}
```

| 字段 | 说明 |
| --- | --- |
| `key` | 离院去向分类（见下表） |
| `count` | 记录数 |
| `pct` | 占比（%）= `count / 总记录数 × 100` |

`key` 分类口径（**固定业务顺序**，前端饼图扇区顺序按此渲染）：

| key | 口径 |
| --- | --- |
| `Home` | 常规出院（`patient_disposition` 含 `Home`） |
| `Transfer/Other Facility` | 转院：短期综合医院 / 联邦医疗机构 / 乡村急救医院 / 精神 / 康复 / 摆动床 |
| `SNF` | 专业护理机构（`Skilled Nursing`） |
| `Hospice` | 临终关怀 |
| `Expired` | 院内死亡 |
| `AMA` | 非医嘱离院（`Left Against Medical Advice`） |
| `Other` | 兜底分类；此外**未能归一化的原始去向**会以原值追加在列表末尾 |

> 分类归一化优先级：`Expired` / `AMA` 优先，转院类次之，`Home` 兜底识别（见 `view.py` 的 `GROUP_CASE`）。原始去向含多个关键字时按此优先级归类。

## 五、维度字典 `GET /meta/dimensions`

本模块无独立的维度枚举接口，`dimension` 取值（`diagnosis`/`facility`/`age_group`/`severity`/`risk_mortality`）所依赖的枚举来自公共接口 `GET /api/v1/meta/dimensions`（诊断 477 项、年龄段 5 档、县 57 个等），详见《病种手术与支付分析接口文档.md》第六章。

> 说明：`risk_mortality` 的枚举值（APR-DRG 预期死亡风险分层）不在 `meta/dimensions` 返回范围内，前端如需预置该维度下拉框，请从 `mortality?dimension=risk_mortality` 的返回结果中取 `name` 动态生成。

## 六、索引清单（DBA/P2 参考）

本模块聚合查询均遵循"先按事实表列/外键 `GROUP BY` 预聚合，后 `JOIN` 小维度表取名"的性能约定（与病种/支付模块一致），并已受《病种手术与支付分析接口文档.md》第七章追加的两条覆盖索引支撑：

- `idx_pay1_pay2 (payment_typology_1, payment_typology_2)` —— 支付相关过滤；
- `idx_age_gender (age_group, gender)` —— 年龄/性别过滤。

本模块高频过滤列（`diagnosis_id`、`facility_id`、`age_group`、`apr_severity_code`、`patient_disposition`、`length_of_stay`）如有慢查询，可在此基础上追加针对性索引，但**务必先 `EXPLAIN` 验证**，且不要使用前缀索引（无法服务 `GROUP BY`）。

## 七、部署与运行

代码结构（每个小功能一个独立子文件夹，模块内公用底座在 `_shared.py`）：
