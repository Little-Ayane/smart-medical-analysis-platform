# 数据入库教程 —— 如何把处理结果放入数据库

> 适用成员：P2（数据预处理）为主，P3 联调参考。目标：把清洗后的 200 万+ 住院数据写入 MySQL 的 `smart_health` 库。

---

## 一、整体流程

```
原始数据（TSV/CSV）
   │  分块读取、清洗、去重、标准化（P2 的 preprocess.py）
   ▼
MySQL 数据库 smart_health
   ├── 4 张维度表（facility / ccsr_diagnosis / ccsr_procedure / apr_drg）
   └── 1 张事实表（fact_inpatient_discharge）
```

---


### 3. 准备数据文件

把原始 TSV/CSV 放到项目下（建议建个 `data/` 目录，已被 `.gitignore` 忽略，不会提交到仓库）：

```bash
mkdir -p data
# 例如：data/hospital.tsv
```

## 三、执行入库

### 方式 1：用项目脚本 `preprocess.py`（推荐）

```bash
python 代码实现/P2_数据预处理/preprocess.py \
    --input data/hospital.tsv \
    --db smart_health \
    --host 127.0.0.1 \
    --user root \
    --password ""
```

参数说明：

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `--input` | 必填 | 原始 TSV/CSV 文件路径 |
| `--db` | `smart_health` | 目标数据库 |
| `--host` | `127.0.0.1` | MySQL 地址 |
| `--user` | `root` | 用户名 |
| `--password` | 空 | 密码（本地开发 root 为空） |

脚本内部逻辑（对理解流程有帮助）：

1. **分块读取** —— 每 10 万条一批，避免内存溢出（`chunksize=100000`）
2. **清洗** —— 缺失值/异常值处理、去重、性别标准化
3. **类型标准化** —— 费用去逗号转浮点、字符串去空格、统一空值
4. **批量入库** —— 每 5000 条一批 `executemany` 写入

### 方式 2：手动 SQL 导入（适合小批量/调试）

```sql
-- 先手工造几条测试数据，验证 P3 接口
INSERT INTO fact_inpatient_discharge
  (age_group, gender, discharge_year, length_of_stay, total_charges, total_costs)
VALUES
  ('30 to 49', 'F', 2021, 5, 12000.00, 8000.00),
  ('50 to 69', 'M', 2021, 8, 25000.00, 15000.00);
```

### 方式 3：pandas 直接写（脚本化备用）

```python
import pandas as pd
from sqlalchemy import create_engine
engine = create_engine("mysql+pymysql://root:@127.0.0.1:3306/smart_health?charset=utf8mb4")
df = pd.read_csv("data/hospital.tsv", sep="\t", chunksize=100000)
for chunk in df:
    chunk.to_sql("fact_inpatient_discharge", engine, if_exists="append", index=False)
```

## 四、验证入库结果

```sql
USE smart_health;

-- 1. 总行数（目标 200 万+）
SELECT COUNT(*) FROM fact_inpatient_discharge;

-- 2. 抽查几条
SELECT * FROM fact_inpatient_discharge LIMIT 5;

-- 3. 按年份聚合（验证 P3 分析接口有数据）
SELECT discharge_year, COUNT(*) AS cnt
FROM fact_inpatient_discharge
GROUP BY discharge_year
ORDER BY discharge_year;
```

入库成功后，重启 P3 服务，访问：

```bash
curl "http://127.0.0.1:5000/api/v1/analysis/aggregate?dimension=discharge_year&metric=count"
```

应能返回非空 `data`。

## 五、⚠️ 当前代码与表结构的不一致（重要）

> **现状**：`preprocess.py` 是「简化版」——它把 `facility_name`、`ccsr_diagnosis_code`、`apr_drg_code` 等**维度字段直接写进事实表**；但 `schema.sql` 的事实表里这些字段已拆到维度表，只留了外键 `facility_id` / `diagnosis_id` / `procedure_id` / `drg_id`。

**影响**：直接跑 `preprocess.py` 会报类似 `Unknown column 'service_area' in 'field list'` 的错误。

**两条路**（二选一，需与 P1 确认后统一）：

| 方案 | 做法 | 适合 |
| --- | --- | --- |
| **A. 改脚本对齐星型模型** | 重写 `to_mysql`：先解析维度表（facility/diagnosis/procedure/drg），再写入事实表外键 | 正式交付（推荐） |
| **B. 改表结构对齐脚本** | 把事实表改成「宽表」，直接放 33 个字段，不拆维度表 | 快速跑通演示 |

> 建议选 A，符合数据库设计的星型模式；如需我协助重写 `to_mysql` 逻辑，可另行安排。

## 六、常见问题

| 问题 | 排查 |
| --- | --- |
| `Can't connect to MySQL` | MySQL 没启动，先 `mysql.server start` |
| `Access denied` | 密码不对（本地 root 已设空密码） |
| `Unknown column` | 见第五节，脚本与表结构不一致 |
| 入库很慢 | 检查 `chunksize`/`batch`，确认字段有索引 |
| 内存溢出 | 确认用了分块读取，别一次性 `read_csv` |
